# Bearer Token Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a backend-only Express service that issues a signed JWT for the configured admin credentials and validates it at `GET /api/me`.

**Architecture:** A single Express server exposes `POST /api/login` and `GET /api/me`. The login route compares configured credentials and issues a one-hour HS256 JWT; the `/api/me` route verifies a Bearer token and returns the username claim. No database or frontend is included.

**Tech Stack:** Node.js, npm, Express, `jsonwebtoken`, `dotenv`.

**Spec:** `docs/superpowers/specs/2026-10-18-bearer-token-auth-design.md`

## Global Constraints

- Keep the deliverable backend-only; add no frontend or database.
- `ADMIN_USERNAME` defaults to `admin`; `ADMIN_PASSWORD` defaults to `password`.
- Require `JWT_SECRET` from the environment; do not provide a production fallback secret.
- Issue tokens with a one-hour expiration and return `expires_in: 3600`.
- Require `Authorization: Bearer <token>` for `GET /api/me`.
- Keep the JSON response contracts and HTTP status codes from the spec.
- Label static credentials as exercise-only in the README.

## Review Focus

- Missing or malformed login JSON should yield a JSON `400` response.
- Wrong username or password should yield `401` without disclosing which value was wrong.
- Missing, malformed, expired, or incorrectly signed Bearer tokens should yield JSON `401`.
- A valid token should return only the expected username in the `user` object.
- Startup without `JWT_SECRET` should fail with a clear configuration error.

### Task 1: Create the Express service and configuration

**Files:**
- Create: `package.json`
- Create: `package-lock.json` (generated by npm)
- Create: `.gitignore`
- Create: `.env.example`
- Create: `src/server.js`

**Interfaces:**
- Produces: an HTTP server on `PORT` or port `3000`, with `POST /api/login` and `GET /api/me`.
- `POST /api/login` consumes `{ "username": string, "password": string }` and on success returns `{ "token": string, "token_type": "Bearer", "expires_in": 3600 }`.
- `GET /api/me` consumes `Authorization: Bearer <token>` and on success returns `{ "user": { "username": string } }`.

- [ ] Create an npm project with `start` and `dev` scripts; add Express, `jsonwebtoken`, and `dotenv` as runtime dependencies.
- [ ] Add `.env` and `node_modules/` to `.gitignore`; create `.env.example` with `PORT`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, and a clearly replaceable `JWT_SECRET` value.
- [ ] In `src/server.js`, load dotenv before reading configuration; default the admin username/password and port as specified; stop startup with a clear error if `JWT_SECRET` is empty.
- [ ] Add JSON request parsing and a JSON error handler so malformed JSON also receives a JSON `400` response.
- [ ] Implement `POST /api/login`: reject missing/non-string credentials as `400` `{ "error": "invalid_request" }`; reject non-matching credentials as `401` `{ "error": "invalid_credentials" }`; otherwise issue an HS256 JWT containing the username with a one-hour expiration and return the specified success body.
- [ ] Implement `GET /api/me`: require a Bearer token, verify it using HS256 and `JWT_SECRET`, return `{ "user": { "username": <claim> } }` on success, and use JSON `401` responses for missing, malformed, expired, or invalid tokens.
- [ ] Start the HTTP server only when `src/server.js` is run directly and use the configured port.
